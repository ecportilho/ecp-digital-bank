Agent anatomy

Agent → Sub-agent → Skill

Each squad agent is built on 3 hierarchical levels. We demonstrate how it works using the Product Manager, its Market Research sub-agent, and the Competitor Analysis skill as examples.

Level 1 · Agent
🧑‍💼

Product Manager

agents/product-manager/

The agent is the highest level in the hierarchy. It is a specialist in a product development discipline — like a senior professional with a specific role within the squad. It does not execute tasks alone: it delegates to specialized sub-agents and consolidates the results.

Role
Product strategy specialist. Operates in Phase 01 (Strategic Context) and Phase 04 (Operations). Never routes tasks to other agents — only to its own sub-agents.
Input
product_briefing_spec.md — functional scope, business rules, target audience.
Output
Objective + Key Results + Opportunity Solution Tree + Product Principles.
Sub-agents
Has 4 sub-agents: Market Research, Product Vision, Product Strategy and Metrics.

💡 Analogy: think of the Product Manager as a sports team head coach. They don't play on the field but define the strategy and field players (sub-agents) at each moment of the match.

Level 2 · Sub-agent
🔍

Market Research

agents/product-manager/subagents/market-research/

The sub-agent is a second-order specialist — focused on a specific subdomain within the parent agent's discipline. It executes tasks using well-defined skills (tools). It's like a senior analyst who reports to the director.

When triggered
Triggered by the Product Manager at the start of Phase 01. It runs first — its findings underpin everything else.
Responsibility
Collect and synthesize market evidence to support strategic decisions.
Available skills
4 skills: market-sizing (TAM/SAM/SOM), competitor-analysis, trend-scanning and customer-segmentation.

💡 Analogy: if the Product Manager is the head coach, Market Research is the analyst in the war room with maps, charts and reports. They have specific tools for each type of analysis.

Level 3 · Skill
⚙️

Competitor Analysis

.../market-research/skills/competitor-analysis.md

The skill is the most concrete and executable level. It is a well-defined tool or procedure with clear input, output and steps. A skill is like a recipe that the AI follows to produce a deterministic result.

Objective
Map direct and indirect competitors, identify gaps and positioning opportunities. Used in Phase 01 to ground OST opportunities with market evidence.
Format
.md file with metadata (name, description), input/output schema and numbered steps.
▶ Input the skill receives
{ "product": "the product", "segment": "string", "depth": "shallow | detailed" }
◀ Output the skill delivers
{ "competitors": [{ "name": "", "type": "direct | indirect", "strengths": [], "weaknesses": [], "positioning": "" }], "market_gaps": [], "differentiation_opportunities": [] }

Steps the skill executes

  1. List direct competitors (e.g., Trello, Notion, Asana, Linear)
  2. List indirect competitors (e.g., spreadsheets, sticky notes)
  3. Analyze strengths and weaknesses of each
  4. Identify unmet gaps
  5. Map differentiation opportunities

💡 Analogy: a skill is like a tool in the analyst's toolbox: a ready-made template that transforms an input into a structured output. The sub-agent chooses which skill to use at each moment, like a carpenter choosing between a saw, hammer or screwdriver.

In practice

How the 3 levels work together

Execution flow in Phase 01

  • The squad Orchestrator calls the Product Manager agent at the start of Phase 01.
  • The Product Manager reads the product briefing and decides to call the Market Research sub-agent first.
  • Market Research reviews available skills and chooses Competitor Analysis to map the competitive landscape.
  • The Competitor Analysis skill receives input (product, segment, depth) and executes the 5 defined steps.
  • The skill returns a structured JSON with competitors, gaps and opportunities.
  • The Market Research sub-agent also runs other skills (market-sizing, trend-scanning, customer-segmentation) and consolidates everything.
  • The Product Manager receives Market Research results and triggers the next sub-agents (Vision, Strategy, Metrics).
  • At the end of Phase 01, the Product Manager delivers the consolidated output (Objective, KRs, OST) and reaches HITL #1 for human approval.

Each level has a CLAUDE.md or .md file that defines its rules, inputs, outputs and behaviors. This makes the squad deterministic, versatile and scalable: new agents can be added without rewriting the system.

Level 1 · Agent 🧑‍💼
agents/product-manager/CLAUDE.md
# 🧑‍💼 Product Manager Agent

## Role
Product strategy specialist. Operates in **Phase 01 (Strategic Context)** and **Phase 04 (Operations)** for A/B monitoring. Never routes tasks to other agents.

## Primary Input
**`{REPO_DESTINO}/product_briefing_spec.md`** — Read BEFORE any action.
This file contains the functional scope, business rules, target audience and product context.

## Sub-agents
| Sub-agent | Folder | Responsibility |
|-----------|--------|----------------|
| Market Research | `subagents/market-research/` | Market, competition and segmentation |
| Product Vision | `subagents/product-vision/` | Vision, North Star and principles |
| Product Strategy | `subagents/product-strategy/` | OKRs, roadmap and 4 risks |
| Metrics | `subagents/metrics/` | KPIs, experiments and A/B |

## Usage by Phase

### Phase 01 — Strategic Context
Trigger sub-agents in order:
1. `market-research` → understand market and segments (using `product_briefing_spec.md` as base)
2. `product-vision` → define objective and principles
3. `product-strategy` → structure KRs and map OST opportunities
4. `metrics` → validate measurability of KRs

**Expected output:** Objective + KRs + complete OST (opportunities per KR: pains, needs and desires)
**Output written to:** `{REPO_DESTINO}/01-strategic-context/`

### Phase 04 — A/B Monitoring
Trigger sub-agent:
- `metrics` → analyze A/B results, impact on KRs and generate feedback recommendation

## Output Format (Phase 01)
```json
{
  "agent": "product-manager",
  "phase": "01-strategic-context",
  "deliverables": {
    "objective": "",
    "key_results": [],
    "opportunity_solution_tree": {},
    "product_principles": []
  },
  "open_questions": [],
  "next_hitl": 1
}
```

## Rules
- ❌ No solutions or features in the OST — only opportunities (pains, needs, desires)
- ❌ Do not define technology or implementation
- ✅ Read `{REPO_DESTINO}/product_briefing_spec.md` as the first action
- ✅ KRs must be measurable with a defined baseline
- ✅ Each opportunity must be linked to a specific KR
- ✅ References: Torres (OST), Cagan (4 risks, vision), Marr (OKRs)
