Chapter 1

Product Overview

Executive summary of FoodFlow — premium food delivery marketplace for São Paulo.

1.1 Vision and Positioning

Product Vision
Premium food delivery marketplace for São Paulo

In 5 years, FoodFlow will be the reference platform for those seeking gastronomic delivery experiences in São Paulo and Brazil’s main capitals — recognized for its impeccable curation of artisan restaurants, the discovery experience that delights, and an integrated payment ecosystem that makes ordering food as pleasurable as eating it.

We will be the bridge between restaurants that care about quality and consumers who value what they eat.

1.2 North Star Metric

North Star Metric
Satisfied Completed Orders per Week

Description: Number of successfully delivered orders (no cancellation and no open complaint) per active week.

Formula: Σ (orders with status ‘Delivered’ and no open complaint ticket within 48h) / week

MVP Target: 630 orders/week (90/day) in the first 3 months

Year 1 Target: 6,300 orders/week (900/day)

Input Metrics

  • Conversion Rate (Visitor-to-Order): Target: > 8%
  • Average Order Value: Target: > R$ 45
  • 30-day Repurchase Rate: Target: > 25%
  • Time to First Order: Target: < 5 minutes
  • Active Restaurants / Week: Target: > 40 (MVP), > 200 (year 1)
  • Consumer NPS: Target: > 40

2.2 5 Product Principles

Principle #1
Discovery first
Every screen must help the consumer find what they want to eat in fewer steps. Trade-off: we prioritize discovery experience even if that means showing fewer restaurants per screen.
Principle #2
Checkout is sacred
From cart to confirmed order, zero distractions and zero surprises. Transparent prices, coupons that work, payment that flows. Trade-off: we prioritize speed and clarity in checkout even if that limits upsell options.
Principle #3
Partner restaurant, not hostage
Restaurants must have real control over their presence: menu, prices, promotions, data. Transparent ranking, no mandatory ‘pay-to-play’. Trade-off: we prioritize transparency even if that reduces paid media revenue.
Principle #4
Design as competitive differentiator
Memorable visual experience: premium dark mode, elegant typography, smooth animations, photos that make you hungry. Trade-off: we invest more time in visual craft.
Principle #5
Data for decisions, not for dashboards
Every metric we collect must inform a concrete decision. If data doesn’t drive action, we don’t show it. Trade-off: few actionable indicators over comprehensive panels.

4.2 DDD Architecture — 6 Bounded Contexts

Identity
Authentication, authorization, sessions and profiles
JWT 24h + Refresh Token 7d. Roles: consumer, restaurant, admin. bcryptjs 12 rounds.
Catalog
Restaurants, categories, menus and items
Public domain (read without auth). 6 seed restaurants, 24 items, 7 categories.
Ordering
Cart, orders, order items, coupons
Status: pending_payment → confirmed → preparing → out_for_delivery → delivered. Free delivery ≥ R$ 120.
Payment
ECP Digital Bank Integration
Values in cents. Circuit breaker (5 failures = 30s block). PIX expires in 10 min. HMAC-SHA256 validation.
Delivery
Simulated delivery tracking
MVP: restaurant updates status manually. No real GPS. ETA calculated via eta_min/eta_max.
Admin
Dashboard and platform management
Metrics: total restaurants, orders, revenue, avg ticket. CRUD restaurants, categories, coupons.

4.3 Sequence Diagram — Full Flow (Order + Payment)

End-to-end flow: from order to payment (ECP Card and PIX QR Code) with ECP Digital Bank integration.

Order + Payment Sequence — ECP Card & PIX QR Code
Flow Resilience Rules
  • Idempotent: same payment.id resent does not duplicate transaction
  • Bank timeout: 10s with 1x retry for 5xx errors
  • Circuit breaker: 5 consecutive failures = 30s block
  • PIX expires: 10 minutes — after expiration, payment.status = ‘expired’
  • Webhook: always returns 200 OK to prevent bank retries
  • SSE auth: short-lived JWT token (5 min) via query param
  • Ephemeral bank JWT: never persisted beyond the transaction

4.4 Architecture Decision Records (ADRs)

ADR-001
Monorepo Single-Server Architecture
Fastify serves REST API (/api/*) + React SPA (client/dist/) in a single Node.js process. Minimum cost (VPS R$ 20-50/month).
ADR-002
SQLite with better-sqlite3 as Primary Database
SQLite via better-sqlite3 11.x with WAL mode. File at ./data/foodflow.db. Inline migrations at startup. Zero-config.
ADR-003
ECP Digital Bank Integration as Payment Proxy
FoodFlow acts as payment proxy. bank-integration.mjs encapsulates all calls. ECP Virtual Card + PIX QR Code with webhook + SSE.
ADR-004
SSE for Real-Time PIX Payment Notification
Server-Sent Events via GET /api/payments/:id/events. Native in browser (EventSource), unidirectional, low overhead.
ADR-005
CSS Modules with CSS Custom Properties for Theming
CSS Modules (*.module.css) for isolated scope + CSS Custom Properties for global Midnight Express theming. Zero runtime JS.
