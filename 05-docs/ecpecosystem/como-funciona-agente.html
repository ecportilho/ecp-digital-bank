Nível 1 · Agente
🧑‍💼

Product Manager

agents/product-manager/

O agente é o nível mais alto da hierarquia. É um especialista em uma disciplina do desenvolvimento de produto — como se fosse um profissional sênior com um papel específico dentro do squad. Ele não executa tarefas sozinho: delega para subagentes especializados e consolida os resultados.

Papel
Especialista em estratégia de produto. Opera na Fase 01 (Contexto Estratégico) e na Fase 04 (Operação). Nunca roteia tarefas para outros agentes — apenas para seus próprios subagentes.
Input
product_briefing_spec.md — escopo funcional, regras de negócio, público-alvo.
Output
Objetivo + Key Results + Opportunity Solution Tree + Princípios de Produto.
Subagentes
Possui 4 subagentes: Market Research, Product Vision, Product Strategy e Metrics.

💡 Analogia: pense no Product Manager como o diretor de um time esportivo. Ele não joga no campo, mas define a estratégia e escala jogadores (subagentes) para cada momento da partida.

Nível 2 · Subagente
🔍

Market Research

agents/product-manager/subagents/market-research/

O subagente é um especialista de segunda ordem — foca em um subdomínio específico dentro da disciplina do agente pai. Ele executa tarefas usando skills (ferramentas) bem definidas. É como um analista sênior que reporta ao diretor.

Quando aciona
Acionado pelo Product Manager no início da Fase 01. É o primeiro a rodar — suas descobertas fundamentam todo o resto.
Responsabilidade
Coletar e sintetizar evidências de mercado para embasar decisões estratégicas.
Skills disponíveis
4 skills: market-sizing (TAM/SAM/SOM), competitor-analysis, trend-scanning e customer-segmentation.

💡 Analogia: se o Product Manager é o diretor, o Market Research é o analista que fica na sala de guerra com mapas, gráficos e relatórios. Ele tem ferramentas específicas para cada tipo de análise.

Nível 3 · Skill
⚙️

Competitor Analysis

.../market-research/skills/competitor-analysis.md

A skill é o nível mais concreto e executável. É uma ferramenta ou procedimento bem definido, com input, output e passos claros. A skill é como uma receita de bolo que a IA segue para produzir um resultado determinístico.

Objetivo
Mapear concorrentes diretos e indiretos, identificar gaps e oportunidades de posicionamento. Usar na Fase 01 para fundamentar as oportunidades da OST com evidências de mercado.
Formato
Arquivo .md com metadados (nome, descrição), schema de input/output e passos numerados.
▶ Input que a skill recebe
{ "product": "o produto", "segment": "string", "depth": "superficial | detalhado" }
◀ Output que a skill entrega
{ "competitors": [{ "name": "", "type": "direct | indirect", "strengths": [], "weaknesses": [], "positioning": "" }], "market_gaps": [], "differentiation_opportunities": [] }

Passos que a skill executa

  1. Listar concorrentes diretos (ex: Trello, Notion, Asana, Linear)
  2. Listar concorrentes indiretos (ex: planilhas, post-its)
  3. Analisar forças e fraquezas de cada um
  4. Identificar gaps não atendidos
  5. Mapear oportunidades de diferenciação

💡 Analogia: a skill é como uma ferramenta na caixa do analista: um gabarito pronto que transforma uma entrada em uma saída estruturada. O subagente escolhe qual skill usar em cada momento, como um marceneiro escolhe entre serra, martelo ou chave de fenda.

Na prática

Como os 3 níveis trabalham juntos

Fluxo de execução na Fase 01

  • O Orquestrador do squad chama o agente Product Manager no início da Fase 01.
  • O Product Manager lê o briefing do produto e decide chamar primeiro o subagente Market Research.
  • O Market Research olha as skills disponíveis e escolhe a Competitor Analysis para mapear o cenário competitivo.
  • A skill Competitor Analysis recebe input (produto, segmento, profundidade) e executa os 5 passos definidos.
  • A skill devolve um JSON estruturado com concorrentes, gaps e oportunidades.
  • O subagente Market Research também roda outras skills (market-sizing, trend-scanning, customer-segmentation) e consolida tudo.
  • O Product Manager recebe o resultado do Market Research e aciona os próximos subagentes (Vision, Strategy, Metrics).
  • Ao fim da Fase 01, o Product Manager entrega o output consolidado (Objetivo, KRs, OST) e atinge o HITL #1 para aprovação humana.

Cada nível tem um arquivo CLAUDE.md ou .md que define suas regras, inputs, outputs e comportamentos. Isso torna o squad determinístico, versátil e escalável: novos agentes podem ser adicionados sem reescrever o sistema.

Definições reais

Os 3 arquivos markdown lado a lado

Estes são os arquivos de definição reais que o squad lê para operar. Cada nível tem seu próprio arquivo .md — é assim que a IA sabe o que fazer em cada etapa.

Nível 1 · Agente 🧑‍💼
agents/product-manager/CLAUDE.md
# 🧑‍💼 Product Manager Agent

## Papel
Especialista em estratégia de produto. Opera na **Fase 01 (Contexto Estratégico)** e na **Fase 04 (Operação)** para monitoramento A/B. Nunca roteia tarefas para outros agentes.

## Input Primário
**`{REPO_DESTINO}/product_briefing_spec.md`** — Ler ANTES de qualquer ação.
Este arquivo contém o escopo funcional, regras de negócio, público-alvo e contexto do produto.

## Subagentes
| Subagente | Pasta | Responsabilidade |
|-----------|-------|-----------------|
| Market Research | `subagents/market-research/` | Mercado, concorrência e segmentação |
| Product Vision | `subagents/product-vision/` | Visão, North Star e princípios |
| Product Strategy | `subagents/product-strategy/` | OKRs, roadmap e 4 riscos |
| Metrics | `subagents/metrics/` | KPIs, experimentos e A/B |

## Uso por Fase

### Fase 01 — Contexto Estratégico
Acionar subagentes na ordem:
1. `market-research` → entender mercado e segmentos (usando `product_briefing_spec.md` como base)
2. `product-vision` → definir objetivo e princípios
3. `product-strategy` → estruturar KRs e mapear oportunidades da OST
4. `metrics` → validar mensurabilidade dos KRs

**Output esperado:** Objetivo + KRs + OST completa (oportunidades por KR: dores, necessidades e desejos)
**Output gravado em:** `{REPO_DESTINO}/01-strategic-context/`

### Fase 04 — Monitoramento A/B
Acionar subagente:
- `metrics` → analisar resultados do A/B, impacto nos KRs e gerar recomendação de retroalimentação

## Formato de Output (Fase 01)
```json
{
  "agent": "product-manager",
  "phase": "01-strategic-context",
  "deliverables": {
    "objective": "",
    "key_results": [],
    "opportunity_solution_tree": {},
    "product_principles": []
  },
  "open_questions": [],
  "next_hitl": 1
}
```

## Regras
- ❌ Nenhuma solução ou feature na OST — apenas oportunidades (dores, necessidades, desejos)
- ❌ Não defina tecnologia ou implementação
- ✅ Ler `{REPO_DESTINO}/product_briefing_spec.md` como primeira ação
- ✅ KRs devem ser mensuráveis e com baseline definido
- ✅ Cada oportunidade deve estar ligada a um KR específico
- ✅ Referências: Torres (OST), Cagan (4 riscos, visão), Marr (OKRs)

# Skill: competitor-analysis

## Objetivo
Mapear concorrentes diretos e indiretos, identificar gaps e oportunidades de posicionamento.

## Input
```json
{
  "product": "o produto",
  "segment": "string",
  "depth": "superficial | detalhado"
}
```

## Output
```json
{
  "competitors": [
    {
      "name": "",
      "type": "direct | indirect",
      "strengths": [],
      "weaknesses": [],
      "positioning": ""
    }
  ],
  "market_gaps": [],
  "differentiation_opportunities": []
}
```

## Passos
1. Listar concorrentes diretos (Trello, Notion, Asana, Linear)
2. Listar concorrentes indiretos (planilhas, post-its)
3. Analisar forças e fraquezas de cada um
4. Identificar gaps não atendidos
5. Mapear oportunidades de diferenciação

💡 Note como o agente (nível 1) é abrangente, o subagente (nível 2) é mais específico e a skill (nível 3) é tão concreta que tem input/output em JSON e passos numerados.
